# Bootstrap versions and dependency ownership

Stable versions were selected against the installed SDKs and verified with the real package managers. This baseline uses .NET 8 and Flutter 3.24.5 to match the local tools; it is not a claim that they are the newest SDKs. Coordinate SDK/support-lifecycle upgrades before long-term use and update CI, documentation, manifests, and generated locks together.

Flutter and flutter_web_plugins come from the pinned SDK. ASP.NET Core comes from the .NET SDK/runtime. Npgsql **8.0.6** is the provider's resolved transitive driver. Every transitive version is recorded in the package-manager-generated lockfiles; the table lists bootstrap dependencies, not a manually maintained transitive dependency inventory.

Track `frontend/package-lock.json`, `backend/src/WasteToValue.Api/packages.lock.json`, `backend/.config/dotnet-tools.json`, and `mobile/pubspec.lock`. They were generated by npm, NuGet/.NET CLI, and Flutter pub. Never fabricate or manually edit lockfiles. Use `npm ci`, NuGet `--locked-mode`, and Flutter `--enforce-lockfile` to restore the baseline. Use npm consistently; do not add Yarn/pnpm lockfiles.

Only the requested clients, API/data provider, routing/HTTP libraries, and generated build/lint support were installed. No state-management package, authentication package, business framework, AI dependency, or agent framework was added.

After bootstrap the leader coordinates all package additions and upgrades through a separate integration PR. Agree on purpose, version compatibility, and ownership first; regenerate the affected lockfile with its package manager, run relevant checks, and review manifest/lock changes together. Keep EF runtime/design/tooling on compatible versions with Npgsql and the target SDK. Avoid four branches editing shared manifests/locks simultaneously.
