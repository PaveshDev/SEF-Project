## Executive Summary

The Recovery module for managing item recovery workflows has substantial implementation complete with 187 backend tests passing. The module correctly implements:

- ✅ Workflow state machines and validations
- ✅ Reference-based valuation with freshness constraints
- ✅ Multi-route planning with dependency tracking
- ✅ Agent resume authorization with strict approvals
- ✅ React browser workflows with CRUD operations

**Critical blockers preventing production use:**
1. Shared authentication system (required for all operations)

## Section 3: INTEGRATION DEPENDENCIES

### Critical: Shared Authentication
**Responsibility:** Shared Infrastructure / Member responsible for auth  
**What Recovery needs:**
- Verified user identity (actor)
- Owner permission checks
- Curator capability (reference verification)
- Human vs agent distinction

**How Recovery uses it:**
- `IRecoveryActorAccessor.GetAsync()` must return current authenticated user
- All controllers require authenticated access
- Reference verification requires curator role
- Currently returns `identity_unavailable` error if not configured

**Required by:** Every operation (create, update, plan, decide)

### High: Items Assessment Gateway
**Responsibility:** Member 1 / Items module  
**What Recovery needs:**
- Current confirmed assessment for an item
- Item ownership verification
- Assessment ID, version, currentness
- Category, condition, function, service area

**Contract:** `IAssessmentGateway.GetCurrentAsync(itemId, cancellationToken)`
- Returns: `GatewayResult<AssessmentSummary>`
- Must validate: item owner matches request actor
- Must provide: ID, version, confirmation status, category, condition

**Used by:**
- Case creation (validate assessment)
- Planning (load reference conditions, categories)
- Proposal submission (revalidate before committing)
- Proposal decision (revalidate before approval)

**Currently:** Returns `Unavailable` (stub)

### High: Partners Matching Gateway
**Responsibility:** Member 3 / Partners module  
**What Recovery needs:**
- Find accepted, eligible matches for an option
- Match version and freshness token
- Revalidate matches during proposal approval

**Contract:** `IMatchingGateway.FindMatchesAsync(MatchRequest, cancellationToken)`
- Input: recovery option ID, category, condition, function, route, service area, deadline
- Returns: List of `MatchSummary` with ID, version, freshness token, eligibility, partner response
- Must validate: match eligibility and partner acceptance
- Required during: Planning (fetch matches) and Decision approval (revalidate)

**Used by:**
- Planning (find suitable matches for transfer routes)
- Decision approval (ensure match still eligible)

**Currently:** Returns `Unavailable` (stub)

### High: Collections Pickup Gateway
**Responsibility:** Member 4 / Collections module  
**What Recovery needs:**
- Plan pickup for a match
- Estimated cost, feasibility, scheduling
- Revalidate pickup during proposal approval

**Contract:** `IPickupPlanningGateway.PlanAsync(PickupRequest, cancellationToken)`
- Input: match ID, service area, route, budget, deadline, currency
- Returns: `PickupPlanSummary` with estimated cost, feasibility, freshness token
- Must validate: cost ≤ budget, deadline feasible
- Required during: Planning (get cost) and Decision approval (revalidate)

**Used by:**
- Planning (get actual pickup cost for routes requiring transfer)
- Decision approval (ensure pickup still feasible and within budget)

**Currently:** Returns `Unavailable` (stub)

### High: Durable Command Execution & Idempotency
**Responsibility:** Shared Infrastructure / Integrator  
**What Recovery needs:**
- Transactional write with idempotency key
- Duplicate protection (same key = same result)
- Stored receipt (for recovery after disconnect)
- Restart-safe replay

**Implementation provided:** `IRecoveryCommandExecutor`
- Must store: actor, operation, key, payload, result
- Must enforce: unique key per operation
- Must retry: same key returns cached result
- Must handle: concurrent duplicate requests

**Used by:** Every mutation (create case, plan, decide, etc.)

**Currently:** Implemented interface exists, needs production storage
